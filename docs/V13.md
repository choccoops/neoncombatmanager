# Moving to Foundry v13

Cyberpunk RED - CORE 0.92 runs on Foundry v12, and this module is built and tested for v12.
It's written to move to v13 with the system, without a rewrite.

## What's already in place

- **One compatibility layer** (`scripts/compat.js`). Every Foundry API that moved or changed
  shape between v12 and v13 is reached through it, preferring v13's namespaced path and falling
  back to v12's global: `renderTemplate`/`loadTemplates`, `FilePicker`, `TextEditor`, `DialogV2`,
  the chat render hook (`renderChatMessage` in v12, `renderChatMessageHTML` in v13), hook HTML
  (jQuery in v12 AppV1 hooks, HTMLElement in v13), scene darkness and global light
  (`scene.environment`), light sources, darkness sources, regions, grid measurement and
  `Actor#toggleStatusEffect`.
- **A guard in `npm run check`**: CI fails if any file other than `compat.js` uses a global that
  v13 moved (`renderTemplate(`, `loadTemplates(`, `new FilePicker`, `TextEditor.`,
  `mergeObject(`, `duplicate(`, `FormDataExtended`).
- **ApplicationV2 only.** The Condition Lab, editor, Triggler, Environment window and settings
  menus are ApplicationV2 + HandlebarsApplicationMixin, which v13 keeps. None assigns AppV2's
  read-only getters (`state`, `element`, `title`...) and no action uses a reserved name
  (`close`, `tab`, `toggleControls`).
- **No Application for the carousel.** It's a plain element fixed to the window and centred over
  `#ui-middle`, which both versions have, so v13's new interface layout doesn't break it.
- **Token-control buttons** for the Biomon Link and holocalls go through
  `Compat.addSceneTools`, which handles v12's control array (`token`, `onClick`) and v13's
  control object (`tokens`, `onChange`).
- **Status effects in v12+ shape** (`id`, `name`, `img`, `hud`), which v13 uses unchanged.
- **Hooks that kept their names**: `renderCombatTracker`, `renderSceneConfig`, `renderTokenHUD`
  (all read through `Compat.element`), `updateCombat`, `combatRound`, `updateWorldTime`,
  `createActiveEffect` and friends.

## Checklist when the system ships for v13

1. Install the system's v13 release on a v13 test world with this module, Neon Hub and
   SmallTime's v13 version.
2. Run `npm run check` and `npm test`.
3. In the world:
   - start a combat: the carousel shows, Next/Previous Turn and Round work, each Round moves
     SmallTime's clock 3 seconds, End Turn works for a player;
   - the sidebar combat tracker shows Wound States (v13's tracker is AppV2: check the
     selectors in `scripts/combat/tracker.js`: `[data-combatant-id]`, `.token-name`);
   - Scene configuration shows the weather select (v13 SceneConfig tabs: check
     `sceneConfig()` finds a tab; v13 names may differ);
   - the token HUD lists the Cyberpunk RED statuses, and toggling one applies its penalty in a
     roll;
   - a Critical Injury from the HUD adds CPR's item; Mortally Wounded prompts a Death Save card;
   - chat card buttons work and holocall messages turn blue (the `renderChatMessageHTML` path);
   - the heart-pulse and phone buttons show in the token controls and open the Biomon Link and
     the dialer; a call rings another user and the conversation works both ways;
   - the Condition Lab, Triggler and Environment windows open, edit and save;
   - weather from Neon Hub and darkness from SmallTime produce Low Light/Darkness on a token.
4. Fix anything found in `compat.js` first (one place), then the caller.
5. Set `"compatibility": { "minimum": "12", "verified": "13" }` in `module.json`, add a
   CHANGELOG section and release.

## Known v13 differences to watch

| Area | v12 | v13 |
| --- | --- | --- |
| Combat tracker | AppV1, jQuery in the render hook | AppV2, HTMLElement; markup changed |
| Scene config | AppV1 tabs `basic/grid/lighting/ambience` | AppV2 tabs; field names may differ |
| Chat render hook | `renderChatMessage(message, $html)` | `renderChatMessageHTML(message, html)` |
| Scene navigation | `#navigation` inside `#ui-top` | `#scene-navigation`, elsewhere |
| Globals | `renderTemplate`, `FilePicker`... | `foundry.applications.*` |
| Lighting | `canvas.effects.lightSources` | same collection; check `source.data.bright/dim` stay in pixels |
